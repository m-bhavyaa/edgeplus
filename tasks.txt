M3  Now we make the simulator event-driven so queues and resources actually evolve over time.

The key change is:

A task assigned at time t occupies memory until its processing finishes. If another task arrives before that, it waits behind the existing work.

What changed?

Previously we had:

server.queue_time += processing
server.memory_used += task.memory

which meant resources effectively stayed occupied forever.

Now the server maintains:

active_jobs
    │
    ├── task 4 → finishes at 3.2
    ├── task 8 → finishes at 5.7
    └── task 12 → finishes at 7.1
When simulation time reaches 5.7, task 8 is automatically released.
